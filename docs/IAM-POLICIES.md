# IAM Policies — HelpUcompli Document Repository

Canonical least-privilege policy documents for the document repository's AWS surface. Defined as code in `src/lib/iam-policies.ts` (validated by unit tests in `src/__tests__/s3/iam-policies.test.ts`) so deploy tooling and documentation stay in lockstep.

## Principles

1. **Least privilege**: app role reads/writes objects inside `helpucompli-docs-*`, enumerates + updates CloudTrail selectors for the single configured trail, and uses the single configured document CMK. It cannot create or delete KMS keys, modify IAM, or start/stop CloudTrail trails.
2. **Defense in depth**: explicit `Deny` statements on ACL writes, KMS lifecycle, IAM writes, and CloudTrail trail-lifecycle actions. Even if a future `Allow` is accidentally widened, these denies take precedence (IAM deny overrides allow).
3. **Bucket-name scoping**: every S3 allow is constrained to the `helpucompli-docs-*` bucket family. A bucket created outside this name pattern is invisible to the app role regardless of its policy.
4. **CMK scoping**: `kms:Decrypt` and `kms:GenerateDataKey` are constrained to the configured `AWS_KMS_KEY_ID` ARN. The app cannot decrypt objects encrypted by any other CMK.

## Roles

### `helpucompli-docs-app-role`

The runtime role attached to the Next.js server (ECS task role / EC2 instance profile / Vercel role ARN). Generated by `buildAppRolePolicy({ kmsKeyArn, cloudTrailArn })`.

**Allow statements**

| Sid                                    | Purpose                                                                                   |
| -------------------------------------- | ----------------------------------------------------------------------------------------- |
| `S3ObjectReadWrite`                    | Object-level read / write / delete / multipart on `helpucompli-docs-*/*`.                 |
| `S3BucketReadAndHipaaProvisioning`     | Bucket create/delete/list + HIPAA config (encryption, versioning, BPA, policy, ownership, logging) on `helpucompli-docs-*`. |
| `S3ListAllMyBucketsForAdminUI`         | `s3:ListAllMyBuckets` (AWS only accepts `*` for this action). Application-layer filter restricts response to managed buckets (F5.1 DB join). |
| `KmsDocumentCmkUsage`                  | `kms:Decrypt`, `kms:GenerateDataKey`, `kms:DescribeKey` on the configured document CMK only. |
| `CloudTrailDataEventWiring`            | `cloudtrail:GetEventSelectors` + `cloudtrail:PutEventSelectors` on the configured trail only (F3.2 read-modify-write pattern). |

**Deny statements** (defense-in-depth)

| Sid                            | Blocks                                                                                          |
| ------------------------------ | ----------------------------------------------------------------------------------------------- |
| `DenyLoggingBucketMutation`    | `s3:PutBucketLogging`, `s3:DeleteBucketLogging` on the access-logs bucket itself — prevents a compromised runtime from silently redirecting the audit trail. |
| `DenyBucketAclMutation`        | `s3:PutBucketAcl`, `s3:PutObjectAcl` — ACLs already disabled via `BucketOwnerEnforced` (F3.2).   |
| `DenyKmsLifecycle`             | `kms:CreateKey`, `kms:ScheduleKeyDeletion`, `kms:CancelKeyDeletion`, `kms:DisableKey`, `kms:PutKeyPolicy`, `kms:CreateGrant`, `kms:RevokeGrant`. |
| `DenyIamAndCloudTrailAdmin`    | `iam:Create*`, `iam:Delete*`, `iam:Attach*`, `iam:Detach*`, `iam:Put*`, `iam:Update*`, `iam:PassRole`, `cloudtrail:CreateTrail`, `cloudtrail:DeleteTrail`, `cloudtrail:StartLogging`, `cloudtrail:StopLogging`, `cloudtrail:UpdateTrail`. Narrowed to the IAM write surface so implicit `iam:GetRole` / `iam:ListRoles` reads required by SDK clients are still permitted. |

### Break-glass / deploy role

NOT implemented in this module. Lives in the Terraform / CDK pipeline and carries the permissions the app role denies (KMS lifecycle, IAM writes, CloudTrail trail management). Use is gated on MFA and audit-logged by CloudTrail.

## Bucket policy

Applied automatically by `createHipaaBucket` (F3.2). Generated by `buildHipaaBucketPolicy(bucket)`:

- `DenyNonHttps`: `s3:*` denied when `aws:SecureTransport=false`. Enforces TLS 1.2+ transit encryption (HIPAA §164.312(e)(1)). Blocks the bucket owner too — admin access must also use HTTPS.

## KMS key policy

Generated by `buildDocumentKmsKeyPolicy({ awsAccountId, appRoleArn })`:

- `RootAccountFullControl`: account-root retains `kms:*` for break-glass. Scope is enforced via the `Principal: arn:aws:iam::<account>:root` field (AWS-canonical pattern — `kms:CallerAccount` Condition is unreliable for KMS key policies because role-session ARNs don't always match).
- `AppRoleEncryptDecrypt`: `kms:Decrypt` / `kms:GenerateDataKey` / `kms:DescribeKey` granted via `Principal: <appRoleArn>` (NOT via `aws:PrincipalArn` Condition — the Condition approach does not reliably match role sessions assumed from the role). **Never** `kms:*`, never `kms:CreateGrant`.

## Deploy runbook

1. Create the document CMK (customer-managed) with key policy `buildDocumentKmsKeyPolicy(...)`. Record the ARN as `AWS_KMS_KEY_ID` in the environment.
2. Create the CloudTrail trail (management events + S3 data events). Record the ARN as the `cloudTrailArn` argument to `buildAppRolePolicy`.
3. Create the IAM role `helpucompli-docs-app-role` with inline policy `buildAppRolePolicy({ kmsKeyArn, cloudTrailArn })`. Attach to the runtime (ECS task role / EC2 instance profile / Vercel).
4. Create the S3 access-logs bucket `helpucompli-docs-access-logs`. Grant the S3 LogDelivery group `WRITE` + `READ_ACP` per AWS docs. Record as `AWS_S3_LOGS_BUCKET`.
5. Enable account-level S3 Block Public Access before any bucket is provisioned.
6. Verify lifecycle rule on every document bucket for `AbortIncompleteMultipartUpload` (7-day window recommended) — safety net for F3.5 abandoned uploads.

## Carry-forward (F11 security hardening)

- Account-level GuardDuty + AWS Config rule for S3 public-access compliance.
- CloudWatch alarm on `DenyBucketAclMutation` / `DenyKmsLifecycle` denies (signals app-role misuse attempt).
- Rotate the app-role credentials via IAM role session duration (≤1 hour) rather than long-lived keys.
- Amazon Macie evaluation for residual PHI discovery.
- S3 Object Lock evaluation for audit/retention-critical buckets (WORM compliance).
